# مسودة عرض Pilot مدفوع محدود

الحالة: مسودة تجارية داخلية، ليست عقدا نهائيا  
الاستخدام: بعد اجتماع اكتشاف ناجح وتقييم ملاءمة العميل

## 1. اسم العرض

Pilot متقن التشغيلي المدفوع لإدارة الصيانة والمرافق

## 2. الهدف

تشغيل متقن في نطاق محدود داخل منشأة أو موقع واحد لإثبات قيمة واضحة في توثيق البلاغات وأوامر العمل وربطها بالمرافق والأصول والتقارير الإدارية.

الهدف ليس تنفيذ تحول رقمي كامل، بل إثبات أن العمل اليومي يمكن نقله من واتساب وExcel والمتابعة الشفهية إلى دورة تشغيل موثقة وقابلة للقياس.

## 3. المدة

المدة المقترحة: 6 إلى 8 أسابيع من تاريخ اعتماد النطاق واستلام الحد الأدنى من بيانات العميل.

أي تأخر في تسليم البيانات أو الموافقات أو إدخال طلبات خارج النطاق قد يمدد الجدول أو يتطلب إعادة ضبط السعر والمدة.

| المرحلة | المدة التقريبية | الناتج |
| --- | ---: | --- |
| اكتشاف وتثبيت النطاق | 3 إلى 5 أيام عمل | نطاق Pilot ومؤشرات النجاح |
| إعداد البيانات والحسابات | أسبوع | مستخدمون، موقع، مرافق، أصول مختارة |
| التدريب والتهيئة | 2 إلى 3 أيام عمل | تدريب مختصر ومسار تشغيل متفق عليه |
| التشغيل الفعلي | 4 إلى 6 أسابيع | أوامر عمل حقيقية وتقارير أسبوعية |
| تقرير نهاية Pilot | أسبوع | تقييم القيمة والتوصية التالية |

## 4. السعر المقترح

هذه الأرقام نطاقات تفاوض داخلية، وليست سعرا عاما منشورا.

| نوع Pilot | السعر المقترح | متى يستخدم؟ |
| --- | ---: | --- |
| Pilot تأسيسي محدود | 15,000 إلى 25,000 ريال | موقع واحد، مستخدمون محدودون، أصول محدودة، بدون تكاملات |
| Pilot تشغيلي أوسع | 25,000 إلى 40,000 ريال | حجم أعلى من المستخدمين أو الأصول أو تقارير ومتابعة أعمق، مع بقاء النطاق محدودا |

أي نطاق يتطلب عدة مواقع، تكاملات، تنظيف بيانات كبير، أو تخصيصات كبيرة يجب ألا يدخل في هذا العرض إلا بتسعير مستقل.

## 5. ما يشمله العرض

| المجال | المشمول |
| --- | --- |
| إعداد العميل | إنشاء حساب/مساحة عمل للعميل ضمن النطاق المتفق عليه |
| المستخدمون | إعداد عدد محدود من المستخدمين والأدوار |
| المرافق | إدخال موقع واحد وبنية مرافق أساسية |
| الأصول | إدخال مجموعة أصول مختارة ببيانات أساسية |
| أوامر العمل | تشغيل دورة أمر العمل من الإنشاء إلى الإغلاق أو الاعتماد |
| التقارير | تقرير أو لوحة متابعة مناسبة للنطاق، وتقرير أسبوعي يدوي/تشغيلي |
| التدريب | جلسة مختصرة للإدارة والمشرفين والفنيين حسب الحاجة |
| الدعم | دعم خلال ساعات العمل وبقناة متفق عليها |
| المتابعة | اجتماع متابعة أسبوعي مختصر |
| نهاية التجربة | تقرير نهاية Pilot مع توصية واضحة |

## 6. ما لا يشمله العرض

| المجال | المستبعد |
| --- | --- |
| التكاملات | ERP، BMS، IoT، SSO، أنظمة مالية أو موارد بشرية |
| واتساب | واتساب رسمي كقناة إشعارات أو بلاغات |
| تطبيق جوال | تطبيق iOS أو Android أصلي |
| الدعم | دعم 24/7 أو استجابة طوارئ ميدانية |
| التخصيص | تعديلات كود كبيرة أو بناء نسخة خاصة للعميل |
| البيانات | تنظيف أو ترحيل تاريخ كامل أو ملفات ضخمة غير منظمة |
| التقارير | تقارير مفتوحة بلا حدود أو نماذج مخصصة عميقة |
| المواقع | تشغيل متعدد المواقع المعقد من البداية |
| الدفع | الدفع الآلي أو الاشتراكات داخل النظام ما لم يذكر صراحة |

## 7. مسؤوليات متقن

1. تأكيد ملاءمة النطاق قبل البدء.
2. إعداد البيئة والمستخدمين والأدوار المتفق عليها.
3. مساعدة العميل في إدخال بيانات البداية ضمن القالب المتفق عليه.
4. تقديم تدريب مختصر للفئات المشمولة.
5. متابعة تشغيل Pilot خلال الفترة المتفق عليها.
6. استقبال البلاغات الفنية المتعلقة باستخدام متقن داخل النطاق.
7. إعداد تقرير أسبوعي وتقرير نهاية Pilot.
8. توضيح أي طلب خارج النطاق قبل تنفيذه أو تسعيره.

## 8. مسؤوليات العميل

1. تسمية صاحب قرار ومالك تشغيل يومي.
2. توفير بيانات المواقع والمرافق والأصول والمستخدمين في القالب المتفق عليه.
3. حضور جلسات التدريب من الأشخاص المعنيين.
4. استخدام متقن في المسار المتفق عليه أثناء Pilot.
5. تزويد متقن بتغذية راجعة أسبوعية.
6. عدم توسيع النطاق أو طلب تكاملات خارج العرض دون اعتماد منفصل.
7. توفير قرار واضح في نهاية Pilot: توسع، اشتراك، تمديد، أو إيقاف.

## 9. مؤشرات النجاح المقترحة

يتم اختيار 3 إلى 5 مؤشرات فقط حسب النطاق:

| المؤشر | طريقة القياس |
| --- | --- |
| عدد البلاغات أو أوامر العمل المسجلة | من النظام أو التقرير الأسبوعي |
| نسبة أوامر العمل المغلقة | مغلقة مقارنة بإجمالي المسجلة |
| وضوح المسؤولية | كل أمر عمل له مسؤول أو حالة واضحة |
| تقليل ضياع البلاغات | مقارنة نوعية مع الوضع السابق |
| معرفة الأصول المتكررة | ظهور أصول أو أقسام متكررة في التقرير |
| التزام الفريق | عدد المستخدمين النشطين أو التحديثات |
| قرار إداري | 1 إلى 3 قرارات تشغيلية مبنية على البيانات |

## 10. شروط الدفع المقترحة

تحتاج إلى اعتماد داخلي ومراجعة قانونية قبل الإرسال الرسمي.

قبل إرسال النسخة الخارجية للعميل، يجب اختيار خيار دفع واحد فقط وعدم ترك بدائل مفتوحة داخل العرض.

خيار آمن:

1. 50% عند اعتماد العرض وبدء الإعداد.
2. 50% قبل بدء التشغيل الفعلي أو خلال الأسبوع الثاني من Pilot.

بديل للتفاوض:

1. 60% عند اعتماد العرض.
2. 40% عند تسليم تقرير نهاية Pilot.

لا تبدأ أعمال إعداد موسعة قبل دفعة بدء واضحة أو موافقة مكتوبة معتمدة.

## 11. آلية الدعم

1. قناة الدعم الأساسية تحدد قبل البدء: بريد إلكتروني أو قناة مراسلة متفق عليها.
2. الدعم خلال أيام وساعات العمل المتفق عليها.
3. البلاغات التي توقف استخدام المسار الأساسي تعطى أولوية أعلى.
4. طلبات التغيير لا تعامل كأعطال، وتسجل وتراجع بشكل مستقل.

## 12. آلية طلبات التغيير

أي طلب خارج النطاق:

1. يسجل في قائمة طلبات التغيير.
2. يصنف: عطل، إعداد، تدريب، تحسين، تخصيص، أو تكامل.
3. يقيم أثره على الوقت والسعر ونجاح Pilot.
4. يقرر بشأنه: ينفذ داخل النطاق، يؤجل لما بعد Pilot، يسعر بشكل مستقل، أو يرفض إذا هدد نجاح التجربة.

## 13. صياغة إرسال مختصرة للعميل

بناء على الديمو واجتماع الاكتشاف، نقترح البدء بـ Pilot تشغيلي مدفوع ومحدود لمدة 6 إلى 8 أسابيع. نختار موقعا واحدا ومسارا واضحا، ونشغل أوامر عمل حقيقية، ثم نقيس القيمة من خلال تقارير أسبوعية وتقرير نهاية تجربة. هذا يحمينا ويحميكم من مشروع مفتوح، ويجعل قرار التوسع مبنيا على دليل تشغيلي.
