# عرض Pilot متقن التشغيلي المدفوع

الحالة: مسودة عميل قابلة للتنقيح قبل الإرسال  
الاستخدام: بعد ديمو ناجح أو اجتماع اكتشاف يؤكد ملاءمة العميل  
ملاحظة: هذه الوثيقة ليست عقدًا قانونيًا نهائيًا، وتحتاج مراجعة بشرية قبل الإرسال الرسمي.

## 1. اسم العرض

**Pilot متقن التشغيلي المدفوع**

تجربة تشغيل محدودة ومضبوطة لتطبيق متقن على نطاق واضح داخل منشأة العميل، بهدف إثبات القيمة التشغيلية قبل أي توسع أكبر.

## 2. لمن يناسب هذا العرض؟

يناسب هذا العرض المنشآت أو فرق التشغيل التي لديها:

- بلاغات صيانة أو تشغيل تتوزع بين واتساب أو مكالمات أو Excel.
- مواقع أو مبانٍ أو مرافق تحتاج متابعة أوضح.
- أصول تحتاج سجلًا تشغيليًا أفضل.
- فريق فني أو مشرفون يحتاجون دورة عمل أوضح.
- رغبة في تجربة متقن على نطاق محدود قبل التوسع.

لا يناسب هذا العرض إذا كان المطلوب من البداية تكاملات كبيرة، تطبيق جوال أصلي، أو تشغيلًا معقدًا متعدد المواقع دون بيانات ومسؤوليات واضحة.

## 3. هدف Pilot

الهدف من Pilot هو تشغيل متقن في نطاق حقيقي ومحدود لإثبات أن العمل اليومي يمكن نقله من متابعة متفرقة إلى دورة تشغيل موثقة:

**بلاغ ← موقع ← أصل ← فني ← إنجاز ← تقرير ← قرار**

يركز Pilot على:

- توثيق البلاغات وأوامر العمل.
- ربط العمل بالمواقع والأصول.
- توضيح مسؤوليات الفريق.
- تحسين المتابعة الأسبوعية.
- إنتاج تقرير نهاية تجربة يساعد على قرار التوسع أو الإيقاف.

## 4. المدة المقترحة

المدة الافتراضية: **8 أسابيع** من تاريخ اعتماد النطاق واستلام الحد الأدنى من بيانات البداية.

يمكن تقليل المدة إلى 6 أسابيع إذا كان النطاق أصغر والبيانات جاهزة، أو إعادة تقديرها إذا زاد التعقيد.

| المرحلة | المدة التقريبية | الناتج |
| --- | ---: | --- |
| تثبيت النطاق والبيانات | أسبوع | نطاق واضح، مستخدمون، مواقع، أصول، ومؤشرات نجاح |
| الإعداد والتدريب | أسبوع | إعداد الحساب، الأدوار، البيانات الأساسية، وتدريب مختصر |
| التشغيل الفعلي | 4 إلى 5 أسابيع | أوامر عمل حقيقية ومتابعة أسبوعية |
| تقرير نهاية Pilot | أسبوع | ملخص القيمة، الفجوات، والتوصية التالية |

## 5. النطاق المقترح

النطاق السخي لأول Pilot مناسب يمكن أن يشمل:

| المجال | الحد المقترح |
| --- | --- |
| المواقع | حتى 3 مواقع إذا كانت البيانات والمسؤوليات واضحة |
| المستخدمون | حتى 25 مستخدمًا نشطًا ضمن أدوار محددة |
| الأصول | حتى 250 أصلًا إذا كانت البيانات جاهزة أو شبه جاهزة |
| أوامر العمل | تشغيل أوامر عمل حقيقية خلال فترة Pilot |
| الأدوار | مدير/مسؤول، مشرف أو مهندس، فني، ومقدم بلاغ عند الحاجة |
| التقارير | تقرير أسبوعي وتقرير نهاية Pilot |
| التدريب | تدريب مختصر للفئات الأساسية، وليس تدريبًا شاملًا لكل موظفي المنشأة |

أي زيادة كبيرة في عدد المواقع أو المستخدمين أو الأصول أو التقارير تحتاج إعادة تقدير للنطاق والسعر.

## 6. ما يشمله العرض

- إعداد مساحة عمل العميل ضمن النطاق المتفق عليه.
- إعداد المستخدمين والأدوار الأساسية.
- إدخال المواقع والمرافق والأصول المختارة من بيانات العميل.
- تشغيل دورة أمر العمل من البلاغ إلى الإغلاق أو الاعتماد.
- تدريب مختصر للإدارة والمشرفين والفنيين حسب الحاجة.
- متابعة أسبوعية قصيرة خلال فترة التشغيل.
- دعم استخدام داخل النطاق عبر قناة متفق عليها.
- تقرير أسبوعي مختصر.
- تقرير نهاية Pilot يتضمن ما تم تشغيله، حجم الاستخدام، الفجوات، والتوصية التالية.

## 7. ما لا يشمله العرض

لا يشمل Pilot ما يلي إلا إذا تم إدخاله صراحة في نطاق مستقل:

- تكاملات ERP أو BMS أو IoT أو SSO أو أنظمة مالية أو موارد بشرية.
- واتساب رسمي كقناة بلاغات أو إشعارات.
- تطبيق iOS أو Android أصلي.
- دعم 24/7 أو استجابة طوارئ ميدانية.
- تخصيصات كود كبيرة أو نسخة خاصة للعميل.
- تنظيف أو ترحيل بيانات ضخم.
- تشغيل متعدد المواقع المعقد دون مالك واضح وبيانات جاهزة.
- تقارير مفتوحة بلا حدود أو نماذج عميقة مخصصة.
- الدفع الآلي أو الاشتراكات داخل النظام إذا لم تذكر صراحة.
- AI أو Predictive Maintenance أو Digital Twin كقدرات حالية ضمن Pilot.

## 8. مسؤوليات متقن

يلتزم فريق متقن خلال Pilot بما يلي:

1. تأكيد نطاق Pilot قبل البدء.
2. إعداد البيئة والمستخدمين والأدوار المتفق عليها.
3. مساعدة العميل في تنظيم بيانات البداية ضمن القالب المتفق عليه.
4. تقديم تدريب مختصر للفئات المشمولة.
5. متابعة تشغيل Pilot خلال الفترة المتفق عليها.
6. استقبال مشاكل الاستخدام الفنية داخل النطاق.
7. إعداد تقرير أسبوعي وتقرير نهاية Pilot.
8. توضيح أي طلب خارج النطاق قبل تنفيذه أو تسعيره.

## 9. مسؤوليات العميل

يلتزم العميل بما يلي:

1. تسمية صاحب قرار ومالك تشغيل يومي.
2. توفير بيانات المواقع والمرافق والأصول والمستخدمين في القالب المتفق عليه.
3. حضور الأشخاص المعنيين لجلسات التدريب.
4. استخدام متقن في المسار المتفق عليه أثناء Pilot.
5. تزويد متقن بتغذية راجعة أسبوعية.
6. عدم توسيع النطاق أو طلب تكاملات خارج العرض دون اعتماد منفصل.
7. توفير قرار واضح في نهاية Pilot: توسع، تمديد، تعديل نطاق، أو إيقاف.

## 10. مؤشرات النجاح

يتم اختيار 3 إلى 5 مؤشرات فقط حسب نطاق العميل، مثل:

| المؤشر | طريقة القياس |
| --- | --- |
| عدد البلاغات أو أوامر العمل المسجلة | من النظام أو التقرير الأسبوعي |
| نسبة أوامر العمل المغلقة | مقارنة بالمجمل خلال فترة Pilot |
| وضوح المسؤولية | كل أمر له مسؤول أو حالة واضحة |
| ربط الأوامر بالمواقع والأصول | نسبة الأوامر المرتبطة ببيانات تشغيلية |
| اكتشاف أصول أو أقسام متكررة | من التقرير الأسبوعي أو تقرير النهاية |
| التزام الفريق بالاستخدام | نشاط المستخدمين والتحديثات |
| قرارات تشغيلية مبنية على البيانات | 1 إلى 3 قرارات أو توصيات واضحة |

## 11. السعر المقترح

يعتمد السعر النهائي على النطاق والبيانات وعدد المستخدمين ومستوى المتابعة.

| نوع Pilot | السعر المقترح | مناسب لـ |
| --- | ---: | --- |
| Pilot مناسب لأول عميل | 15,000 إلى 25,000 ريال | نطاق محدود وسخي، حتى 3 مواقع عند وضوح البيانات والمسؤوليات |
| Pilot أوسع | 25,000 إلى 40,000 ريال | حجم أعلى أو بيانات أصعب أو متابعة أعمق مع بقاء النطاق محدودًا |

الأسعار لا تشمل أي تكاملات أو تخصيصات كبيرة أو خدمات خارج النطاق المذكور.

## 12. شروط الدفع

الشروط المقترحة:

1. **50%** عند اعتماد العرض وبدء الإعداد.
2. **50%** قبل بدء التشغيل الفعلي أو خلال الأسبوع الثاني من Pilot.

يمكن تعديل شروط الدفع باتفاق مكتوب قبل البدء.

## 13. الدعم أثناء Pilot

- قناة الدعم: يتم الاتفاق عليها قبل البدء.
- ساعات الدعم: خلال ساعات العمل المتفق عليها.
- نوع الدعم: مشاكل استخدام متقن داخل نطاق Pilot.
- لا يشمل الدعم: تشغيل ميداني، طوارئ 24/7، أو طلبات خارج النطاق.

## 14. طلبات التغيير

أي طلب خارج النطاق يتم التعامل معه كالتالي:

1. يسجل الطلب.
2. يقيّم أثره على الوقت والسعر والنجاح.
3. يصنف إلى:
   - يؤجل لما بعد Pilot.
   - يسعر بشكل مستقل.
   - يرفض إذا كان يهدد نجاح التجربة.

لا يتم تنفيذ أي طلب تغيير مؤثر دون اعتماد واضح.

## 15. الخطوة التالية

للبدء، نحتاج:

1. اجتماع اكتشاف مختصر لتأكيد الملاءمة.
2. تحديد المواقع والأصول والمستخدمين المشمولين.
3. تسمية صاحب القرار ومالك التشغيل اليومي.
4. اعتماد النطاق والسعر والمدة.
5. تزويد متقن ببيانات البداية.

بعد ذلك يبدأ الإعداد وفق الجدول المتفق عليه.
