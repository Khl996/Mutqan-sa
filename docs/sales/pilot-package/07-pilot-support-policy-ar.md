# سياسة دعم مختصرة للـ Pilot

الحالة: مسودة تشغيلية  
الاستخدام: ترفق أو تلخص في عرض Pilot

## الهدف

توضيح كيف سيقدم متقن الدعم خلال Pilot، وما الفرق بين عطل داخل النطاق وطلب تغيير أو توسع.

## 1. ساعات الدعم

الاقتراح الافتراضي لأول Pilot:

| البند | السياسة |
| --- | --- |
| أيام الدعم | من الأحد إلى الخميس |
| ساعات الدعم | 9:00 صباحا إلى 5:00 مساء بتوقيت السعودية |
| العطل الأسبوعية والرسمية | ليست ضمن الدعم إلا باتفاق خاص |
| الطوارئ الميدانية | ليست ضمن مسؤولية متقن |

يمكن تعديل الساعات في العرض الرسمي إذا لزم، لكن لا يضاف دعم 24/7 لأول Pilot دون تسعير منفصل.

## 2. قناة الدعم

تحدد قناة واحدة أساسية قبل البداية:

1. بريد إلكتروني رسمي.
2. أو قناة مراسلة متفق عليها للتنسيق فقط.
3. أو نموذج متابعة داخلي إذا تم اعتماده.

يجب تجنب استقبال الطلبات عبر قنوات كثيرة لأن ذلك يعيد نفس مشكلة ضياع البلاغات.

## 3. مستويات الأولوية

| الأولوية | الوصف | زمن استجابة أولي مقترح |
| --- | --- | ---: |
| حرج | مانع لاستخدام المسار الأساسي المتفق عليه | خلال 4 ساعات عمل |
| عالي | يؤثر على مستخدمين أساسيين لكن يوجد بديل مؤقت | خلال يوم عمل |
| عادي | سؤال استخدام، إعداد، أو مشكلة غير مانعة | خلال يومي عمل |
| منخفض | تحسين أو طلب غير عاجل | يناقش في المتابعة الأسبوعية |

زمن الاستجابة لا يعني دائما زمن الحل. بعض المشاكل تحتاج فحصا أو قرار نطاق.

## 4. ما يتم دعمه داخل النطاق

1. مشاكل تسجيل الدخول للمستخدمين المشمولين.
2. مشاكل استخدام المسار المتفق عليه لأوامر العمل.
3. أخطاء واضحة تمنع إنشاء أو تحديث أو إغلاق أمر عمل ضمن النطاق.
4. أسئلة مرتبطة بالمرافق أو الأصول المشمولة.
5. توجيه بسيط للمستخدمين أثناء الفترة الأولى.
6. مراجعة مؤشرات التقرير الأسبوعي.

## 5. ما لا يتم دعمه داخل النطاق

1. تشغيل مواقع أو أقسام غير مشمولة.
2. تدريب أعداد كبيرة خارج القائمة المتفق عليها.
3. تنظيف بيانات خارج القالب أو بكميات كبيرة.
4. بناء تقارير جديدة غير متفق عليها.
5. تكاملات خارجية.
6. واتساب رسمي أو تطبيق جوال أصلي.
7. دعم أجهزة أو شبكة العميل أو أعطال ميدانية.
8. إدارة فريق الصيانة نيابة عن العميل.

## 6. الفرق بين Bug وطلب تغيير

| النوع | التعريف | التعامل |
| --- | --- | --- |
| Bug | سلوك خاطئ يمنع وظيفة متفق عليها من العمل كما يفترض | يعالج ضمن الدعم |
| إعداد | تعديل بيانات أو صلاحية أو ترتيب ضمن الإمكانيات الحالية | يعالج إذا كان داخل النطاق |
| تدريب | عدم معرفة المستخدم بطريقة العمل | يعالج بالتوجيه أو جلسة مختصرة |
| طلب تغيير | طلب ميزة أو تقرير أو مسار جديد غير متفق عليه | يسجل ويقيم |
| توسع نطاق | إضافة مواقع أو فرق أو أصول أو تكاملات كبيرة | يؤجل أو يسعر مستقلا |

## 7. آلية استقبال الدعم

كل طلب دعم يجب أن يحتوي على:

1. اسم المستخدم.
2. الدور.
3. وصف المشكلة.
4. رابط الصفحة أو اسم الشاشة إن وجد.
5. صورة شاشة عند الحاجة.
6. هل المشكلة تمنع العمل أم يوجد بديل؟
7. وقت حدوث المشكلة.

## 8. المتابعة الأسبوعية

تراجع طلبات الدعم أسبوعيا لتحديد:

1. مشاكل متكررة تحتاج تدريب.
2. أخطاء حقيقية تحتاج إصلاح.
3. طلبات تغيير يجب تأجيلها أو تسعيرها.
4. قرارات تشغيلية يجب اتخاذها من العميل.

## صياغة آمنة للعرض

يشمل Pilot دعما تشغيليا محدودا خلال ساعات العمل للمستخدمين والمسار المتفق عليه. أي طلب خارج النطاق أو تخصيص أو تكامل يسجل كطلب تغيير ويقيم قبل تنفيذه.
