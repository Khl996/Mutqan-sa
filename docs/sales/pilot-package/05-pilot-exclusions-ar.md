# قائمة الاستثناءات وحدود النطاق

الحالة: مسودة داخلية ومرفق محتمل للعرض  
الاستخدام: لحماية متقن والعميل من توقعات غير واضحة في أول Pilot

## القاعدة

أول Pilot ليس مشروعا مفتوحا ولا نسخة مخصصة للعميل. أي بند خارج النطاق يجب أن يذكر صراحة في العرض مع سعر ومدة ومسؤوليات، أو يؤجل لما بعد Pilot.

## الاستثناءات الأساسية

| البند المستبعد | التوضيح |
| --- | --- |
| ERP integrations | لا يشمل الربط مع أنظمة مالية أو موارد بشرية أو مشتريات أو ERP |
| BMS integrations | لا يشمل الربط مع أنظمة إدارة المباني أو التحكم |
| IoT integrations | لا يشمل استقبال بيانات حساسات أو أجهزة ميدانية |
| WhatsApp رسمي | لا يشمل قناة واتساب رسمية للبلاغات أو الإشعارات |
| تطبيق جوال أصلي | لا يشمل تطبيق iOS أو Android أصلي |
| دعم 24/7 | لا يشمل دعم طوارئ على مدار الساعة |
| تخصيصات كود كبيرة | لا يشمل بناء مزايا مخصصة أو نسخة خاصة |
| تقارير مفتوحة بلا حدود | لا يشمل بناء أي تقرير يطلبه العميل بلا ضوابط |
| تنظيف بيانات ضخم | لا يشمل تنظيف آلاف السجلات أو تاريخ طويل غير منظم |
| تشغيل متعدد المواقع المعقد | لا يشمل تشغيل عدة مواقع أو مناطق من البداية |
| الدفع الآلي | لا يشمل بوابات دفع أو اشتراكات آلية إلا إذا دخلت صراحة في النطاق |
| جرد ميداني | لا يشمل زيارة ميدانية لحصر كل الأصول |
| التزام SLA قانوني | لا يشمل التزام تعاقدي صارم بزمن إصلاح ميداني |
| ترحيل تاريخ كامل | لا يشمل نقل سنوات من أوامر العمل السابقة |
| تدريب كل الموظفين | لا يشمل تدريب شامل لكل موظفي المنشأة |

## عبارات آمنة عند سؤال العميل

### إذا طلب واتساب

الصياغة المقترحة:

واتساب قناة مهمة في بيئات التشغيل، لكن أول Pilot سيركز على توثيق دورة العمل داخل متقن. يمكن تسجيل طلب واتساب كمرحلة لاحقة أو نطاق منفصل بعد إثبات القيمة الأساسية.

### إذا طلب تطبيق جوال

الصياغة المقترحة:

التطبيق الجوال الأصلي ليس ضمن نطاق أول Pilot. نركز الآن على المسار التشغيلي الأساسي من البلاغ إلى التقرير، ثم نقرر أولوية التطبيق بناء على الاستخدام الفعلي.

### إذا طلب تكاملات

الصياغة المقترحة:

التكاملات تحتاج دراسة مستقلة لأنها تعتمد على النظام الآخر والصلاحيات والبيانات. يمكن تسجيلها في خارطة ما بعد Pilot، لكن لا نجعلها شرطا قبل إثبات القيمة الأساسية.

### إذا طلب كل المواقع

الصياغة المقترحة:

الأفضل أن نبدأ بموقع واحد حتى نقيس القيمة ونضبط المسار. بعد نجاح Pilot يمكن توسيع النطاق تدريجيا بمخاطر أقل.

### إذا طلب تقارير مفتوحة

الصياغة المقترحة:

سنحدد مؤشرات تشغيلية أساسية للتجربة. أي تقرير مخصص كبير يسجل كطلب تغيير أو مرحلة لاحقة حتى لا يتحول Pilot إلى مشروع تقارير مفتوح.

## ما يمكن قبوله بشروط

| الطلب | متى يمكن قبوله؟ |
| --- | --- |
| عدد أصول أعلى قليلا | إذا كانت البيانات نظيفة ولا تزيد عبء الإعداد كثيرا |
| مستخدمون إضافيون | إذا كانوا ضمن الأدوار نفسها ولا يحتاجون تدريبا منفصلا |
| تقرير إضافي بسيط | إذا كان مبنيا على بيانات موجودة ولا يحتاج تطويرا كبيرا |
| جلسة تدريب إضافية | إذا تم تسعيرها أو كانت ضمن حدود زمنية معقولة |
| قسم إضافي داخل نفس الموقع | إذا لم يغير المسار ولا يضاعف البيانات |

## ما يجب رفضه في أول Pilot

1. "نريد كل المواقع من البداية وبنفس السعر".
2. "ابدأوا مجانا، وإذا نجح ندفع".
3. "لا نريد تحديد نطاق، نرى أثناء التجربة".
4. "يجب أن يتكامل مع أنظمتنا قبل أي استخدام".
5. "نريد تطبيق جوال وواتساب رسمي الآن".
6. "نريد دعم 24/7 ضمن السعر".
7. "نريد نقل كل التاريخ السابق قبل التشغيل".

## قاعدة قرار

إذا كان الطلب يساعد على إثبات مسار التشغيل الأساسي خلال 6 إلى 8 أسابيع، يمكن دراسته. إذا كان الطلب يوسع المنتج أو يخلق التزاما مفتوحا أو يؤخر التشغيل، يؤجل أو يسعر بشكل مستقل أو يرفض.
