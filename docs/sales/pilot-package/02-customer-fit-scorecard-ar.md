# نموذج تقييم ملاءمة العميل لأول Pilot

الحالة: مسودة استخدام داخلي  
الاستخدام: بعد اجتماع الاكتشاف وقبل إرسال عرض Pilot

## الهدف

تحديد هل العميل مناسب لأول Pilot مدفوع الآن، مناسب لاحقا بعد تضييق النطاق، أم خطر على متقن ويجب رفضه أو تأجيله.

التقييم لا يقيس "هل العميل مهم؟" بل يقيس "هل نستطيع إنجاح تجربة محدودة معه الآن؟"

## التصنيف المختصر

| التصنيف | معنى التصنيف | القرار |
| --- | --- | --- |
| مناسب لأول Pilot | يوجد ألم واضح، نطاق محدود، مالك يومي، بيانات أولية، وقبول للاستثناءات | نرسل عرض Pilot محدود |
| مناسب لاحقا | العميل جيد لكن نطاقه أو جاهزيته أكبر من قدرتنا الحالية | نؤجل أو نعيد النطاق |
| خطر الآن | المتطلبات مفتوحة أو غير منضبطة أو بلا مالك أو مشروطة بتكاملات | نرفض أو نؤجل بوضوح |

## 1. معايير العميل المناسب لأول Pilot

العميل مناسب إذا تحققت أغلب البنود التالية:

| المعيار | علامة الملاءمة |
| --- | --- |
| النطاق | موقع واحد أو نطاق تشغيلي واحد قابل للعزل |
| الحجم | عدد مستخدمين محدود، وعدد أصول قابل للإدخال والمراجعة |
| الألم | ضياع بلاغات، ضعف متابعة، غياب تاريخ للأصول، أو صعوبة تقارير |
| الملكية | صاحب قرار معروف ومالك تشغيل يومي محدد |
| البيانات | توجد بيانات أولية أو استعداد جاد لتجهيزها |
| الفريق | فنيون ومشرفون مستعدون لتجربة مسار حقيقي |
| التوقعات | يقبل أن Pilot لا يشمل كل المزايا والتكاملات |
| الدعم | يقبل ساعات دعم محددة وقناة دعم واضحة |
| القرار | يوجد مسار اعتماد مالي واضح للتجربة |

## 2. معايير العميل المناسب لاحقا

العميل مناسب لاحقا إذا كان لديه فرصة حقيقية، لكن أحد العوامل التالية يحتاج ضبطا قبل العرض:

| الحالة | سبب التأجيل | القرار المقترح |
| --- | --- | --- |
| عدة مواقع من البداية | يزيد عبء الإعداد والمتابعة | اختيار موقع واحد كبداية |
| بيانات غير جاهزة | سيتحول Pilot إلى مشروع تنظيف بيانات | طلب قالب بيانات أولي قبل العرض |
| يريد PM ومخزون وتخصيصات معا | النطاق كبير على أول تجربة | تقسيم النطاق إلى مرحلة أولى وثانية |
| صاحب القرار غير حاضر | احتمال توقف البيع بعد وقت طويل | طلب اجتماع مع صاحب القرار |
| التشغيل اليومي غير محدد | لا يوجد من يدفع الاستخدام داخل العميل | تسمية مالك Pilot |
| يريد تقييم داخلي طويل | قد يتحول إلى تجربة مجانية غير محددة | وضع مدة وقرار خروج واضح |

## 3. معايير العميل الخطر الآن

يجب رفض أو تأجيل العميل إذا ظهرت عدة إشارات من التالية:

| إشارة الخطر | لماذا خطيرة؟ | الإجراء |
| --- | --- | --- |
| يطلب تجربة مجانية مفتوحة | تستنزف الوقت ولا تثبت جدية | رفض التجربة المفتوحة |
| لا يوجد صاحب قرار | احتمال عدم التحول بعد الجهد | عدم إرسال عرض رسمي |
| لا يوجد مالك تشغيل يومي | الاستخدام سيفشل حتى لو النظام جاهز | طلب مالك قبل أي Pilot |
| يشترط واتساب رسمي من البداية | خارج نطاق أول Pilot الحالي | استبعاد أو تسعير لاحق |
| يشترط تطبيق جوال أصلي | وعد غير جاهز للبيع الآن | رفض الشرط في أول Pilot |
| يشترط ERP/BMS/IoT | يحول Pilot إلى مشروع تكامل | استبعاد أو مشروع مستقل |
| يريد تشغيل كل المواقع | يرفع المخاطر التشغيلية | اختيار موقع واحد أو الرفض |
| يريد دعم 24/7 | عبء لا يناسب مرحلة أول عميل | رفض أو عقد دعم مستقل لاحقا |
| يطلب تخصيص كود كبير | يضعف المنتج ويؤخر البيع | تأجيل لما بعد إثبات القيمة |
| لا يستطيع توفير بيانات | سيظهر متقن فارغا أو ضعيف القيمة | لا يبدأ Pilot |

## نموذج درجة الملاءمة

استخدم درجة من 1 إلى 5 لكل محور.

| المحور | 1 | 3 | 5 | الدرجة |
| --- | --- | --- | --- | ---: |
| وضوح الألم | فضول عام | مشكلة معروفة | ألم يومي مؤثر |  |
| قابلية تضييق النطاق | يريد كل شيء | يقبل بعض التضييق | موقع ومسار واضح |  |
| جاهزية البيانات | لا توجد | جزئية | Excel أو مالك بيانات جاهز |  |
| صاحب القرار | مجهول | غير مباشر | حاضر أو مؤكد |  |
| مالك التشغيل اليومي | غير موجود | محتمل | محدد بالاسم |  |
| قبول الاستثناءات | يرفض الحدود | يقبل جزئيا | يقبل نطاق Pilot |  |
| الاستعداد للدفع | غير واضح | قابل للنقاش | ميزانية أو موافقة أولية |  |
| قابلية إثبات القيمة | صعبة | متوسطة | واضحة خلال 6 إلى 8 أسابيع |  |

## قاعدة تنفيذية

لا نرسل عرض Pilot مدفوع إذا لم يوجد نطاق واضح ومالك تشغيل يومي. وجود عميل كبير لا يكفي. نجاح أول Pilot أهم من حجم الاسم.
