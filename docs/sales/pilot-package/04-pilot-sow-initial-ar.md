# SOW أولي لأول Pilot

الحالة: مسودة نطاق عمل أولي، تحتاج مراجعة قبل الإرسال  
الاستخدام: مرفق أو أساس لعرض Pilot المدفوع

## 1. الغرض

تحديد نطاق عملي ومحدود لتشغيل متقن لأول عميل مدفوع دون تحويل التجربة إلى مشروع مفتوح.

## 2. نطاق البداية

| البند | النطاق المقترح |
| --- | --- |
| عدد المواقع | موقع واحد فقط |
| عدد المباني | 1 إلى 3 مبان أو أقسام رئيسية |
| عدد الطوابق/الأقسام | حسب الحاجة، بحد عملي محدود |
| عدد الأصول | 30 إلى 150 أصل كبداية مناسبة |
| عدد المستخدمين | 5 إلى 20 مستخدما نشطا |
| الأدوار | مدير/مسؤول، مشرف أو مهندس، فني، مقدم بلاغ عند الحاجة |
| مدة Pilot المقترحة | 6 إلى 8 أسابيع من اعتماد النطاق واستلام الحد الأدنى من البيانات |
| قنوات الدعم | قناة واحدة متفق عليها |
| التقارير | تقرير أسبوعي وتقرير نهاية Pilot |

أي زيادة كبيرة على هذه الحدود يجب أن تؤثر على السعر والمدة أو تؤجل لما بعد Pilot. كما أن تأخر العميل في تسليم البيانات أو الموافقات يمدد الجدول ولا يعد تأخرا من متقن.

## 3. الوحدات المشمولة

### أ. المرافق

1. إدخال الموقع المختار.
2. إدخال المباني أو الأقسام الأساسية.
3. ربط الأصول بالموقع أو القسم عند توفر البيانات.

### ب. الأصول

1. إدخال أصول مختارة ببيانات أساسية.
2. البيانات الأساسية تشمل: اسم الأصل، الكود إن وجد، النوع، الموقع، الحالة، الملاحظات.
3. لا يشمل ذلك تدقيق أصول ميداني شامل أو جردا كاملا.

### ج. أوامر العمل

1. إنشاء أوامر عمل أو بلاغات ضمن المسار المتفق عليه.
2. تعيين أوامر العمل لفنيين أو مسؤولين.
3. تحديث الحالات أثناء التنفيذ.
4. إكمال العمل أو رفعه للاعتماد حسب الدور.
5. إغلاق أو اعتماد أوامر العمل حسب المسار المتفق عليه.

### د. التقارير

1. تقرير أسبوعي مختصر.
2. مؤشرات أساسية عن البلاغات وأوامر العمل.
3. إبراز الأصول أو الأقسام المتكررة عند توفر بيانات كافية.
4. تقرير نهاية Pilot مع توصية التوسع.

### هـ. التدريب

1. جلسة تعريفية للإدارة والمشرفين.
2. جلسة مختصرة للفنيين.
3. توضيح المسار العملي المتفق عليه.
4. لا يشمل تدريب كل موظفي المنشأة إلا إذا أضيف للنطاق.

## 4. ما يتم تشغيله فعليا

الحد الأدنى المقبول لاعتبار Pilot حقيقيا:

1. إدخال بيانات موقع وأصول كافية.
2. إنشاء أو استقبال أوامر عمل حقيقية.
3. تعيين جزء من أوامر العمل لفنيين.
4. تحديث الحالات أثناء التنفيذ.
5. إغلاق أو اعتماد أوامر عمل.
6. مراجعة تقرير أسبوعي مع العميل.
7. إصدار تقرير نهاية Pilot.

## 5. مراحل التنفيذ

المدد أدناه تقديرية وقد تتداخل بعض المراحل. لا يبدأ احتساب مدة Pilot التشغيلية قبل اعتماد النطاق واستلام الحد الأدنى من البيانات المطلوبة.

| المرحلة | المدة | مسؤولية رئيسية | الناتج |
| --- | ---: | --- | --- |
| تأكيد النطاق | 3 إلى 5 أيام عمل | متقن والعميل | SOW معتمد ومؤشرات نجاح |
| جمع البيانات | أسبوع | العميل، بدعم متقن | قالب بيانات مكتمل بالحد الأدنى |
| الإعداد | أسبوع | متقن | بيئة ومستخدمون وبيانات بداية |
| التدريب | 2 إلى 3 أيام عمل | متقن والعميل | مستخدمون يعرفون المسار |
| التشغيل | 4 إلى 6 أسابيع | العميل، بدعم متقن | أوامر عمل حقيقية وتقارير |
| التقييم | أسبوع | متقن والعميل | تقرير نهاية Pilot وقرار التوسع |

## 6. متطلبات من العميل قبل البدء

1. موافقة مكتوبة على النطاق والسعر.
2. تسمية صاحب قرار.
3. تسمية مالك تشغيل يومي.
4. تسليم بيانات البداية في القالب المتفق عليه.
5. تحديد المستخدمين والأدوار.
6. تحديد موعد التدريب.
7. قبول قائمة الاستثناءات.

## 7. مؤشرات النجاح

يجب الاتفاق على مؤشرات قليلة وواضحة:

| المؤشر | الهدف المقترح |
| --- | --- |
| تشغيل أوامر عمل حقيقية | نعم، وليس ديمو داخلي فقط |
| استخدام الأدوار الأساسية | مدير/مشرف/فني على الأقل |
| إغلاق أو اعتماد أوامر عمل | خلال فترة التشغيل |
| ظهور مؤشرات إدارية | تقرير أسبوعي قابل للنقاش |
| تحديد قرار نهاية Pilot | اشتراك، توسع، تمديد محدود، أو إيقاف |

6. تقارير غير محدودة.
7. تنظيف بيانات ضخم.
8. تشغيل عدة مواقع معقدة.

## 9. معيار قبول نهاية Pilot

يعتبر Pilot مكتمل التنفيذ إذا:

1. تم تشغيل النطاق المتفق عليه لمدة كافية.
2. تم تسجيل عدد معقول من أوامر العمل أو البلاغات حسب واقع العميل.
3. تم عقد مراجعات أسبوعية أو توثيق بديل لها.
4. تم إصدار تقرير نهاية Pilot.
5. تم تسليم توصية واضحة للمرحلة التالية.

لا يشترط نجاح Pilot أن يتم حل كل طلب أو تنفيذ كل تحسين. نجاحه يقاس بإثبات القيمة داخل النطاق.
