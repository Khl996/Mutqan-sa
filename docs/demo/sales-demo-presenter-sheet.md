# Noura Gardens Sales Demo Presenter Sheet

Status: live-call quick reference  
Demo tenant: Noura Gardens Compound Demo  
Scope: controlled Pilot v1 sales demo

## Demo Objective

Show how Mutqan turns scattered maintenance activity into connected operational memory: work order, asset context, proof of work, PM, and a management decision.

## Opening Line

"I will keep this demo focused on one controlled Pilot v1 story: how a maintenance issue becomes a managed record, connects to an asset, creates proof of work, and ends with a practical decision."

## Exact Screen Sequence

1. Dashboard.
2. Work Orders list.
3. `DEMO-WO-ASSIGNED-001`.
4. `DEMO-WO-COMPLETE-001`.
5. `DEMO-WO-CANCEL-001` if needed.
6. `DEMO-AHU-3A` asset detail.
7. `DEMO-WO-PM-001`.
8. Reports page Decision Brief.

## Screen Talking Points

| Screen | Say |
| --- | --- |
| Dashboard | Confirm this is the Noura Gardens demo tenant. Use it only for context, then move into the work story. |
| Work Orders list | Informal demand becomes controlled work. Point out statuses and preventive vs corrective distinction. |
| `DEMO-WO-ASSIGNED-001` | Every work order has context: asset, location, owner, due date, priority, and workflow position. |
| `DEMO-WO-COMPLETE-001` | Completion keeps notes, timestamps, and evidence where available. This is proof of work. |
| `DEMO-WO-CANCEL-001` | Cancellation is documented, not deleted. Duplicate or invalid work still remains traceable. |
| `DEMO-AHU-3A` asset | Completed work becomes asset history. The asset becomes operational memory, not just a register. |
| `DEMO-WO-PM-001` | PM is connected to assets and work orders. Planned work uses the same operational record. |
| Reports Decision Brief | End with action: escalate overdue work, investigate repeated demand, monitor PM, restock, or rebalance workload. |

## Six Core Value Messages

- No more scattered maintenance memory.
- Every work order has context.
- Completed work becomes asset history.
- PM is connected to assets and work orders.
- Reports end with an action.
- Cancellation is documented, not deleted.

## Careful Objection Handling

| Objection | Answer |
| --- | --- |
| IoT/BMS/BIM/AI | "Those are future directions or separately scoped work. Pilot v1 proves the operational foundation first." |
| Mobile app | "Do not assume a native mobile app unless it is ready and verified. For Pilot v1, validate browser-based workflows with controlled users." |
| ERP | "Mutqan is not an ERP. It is an operations, maintenance, and asset-management foundation that can coexist with ERP later." |
| Customization | "Pilot v1 is configuration-led. We adapt supported roles, labels, locations, categories, PM schedules, and workflows without promising custom code." |
| Only work orders | "That is a valid starting point, but connecting work orders to locations and assets is what turns tickets into operational memory." |
| Implementation timeline | "A narrow controlled pilot can often be framed around 2 to 4 weeks if data is ready; broader scope needs a longer agreed timeline." |

## What Not To Show

- Passwords or credential handling.
- Billing or subscription internals.
- Deep admin settings.
- Migration, security, database, or raw technical logs.
- Public portal unless verified for that prospect.
- Future IoT, BMS, BIM, AI, or native mobile as if already live.
- Unverified integrations or unlimited customization.

## Controlled Pilot Close

"The right next step is a controlled pilot, not a full transformation project on day one. We choose one facility, building, asset group, or team, load the minimum useful data, and prove that Mutqan can document work, connect it to assets and locations, preserve proof of work, and give managers useful decision signals."

"For a narrow scope, we can frame this around 2 to 4 weeks if the starter data is ready. In the next meeting, we should confirm the pilot owner, sponsor, users, location hierarchy, starter assets, PM scope if included, success criteria, and go/no-go conditions."

## Final Reminder

Keep the demo practical. Do not tour the product. Tell one story: issue, work order, asset memory, PM, report, decision.
