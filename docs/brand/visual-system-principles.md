# Mutqan Visual System Principles

## Purpose
This document defines the foundational visual system principles for Mutqan. It guides graphics, illustrations, iconography, product screenshots, marketing visuals, sales materials, and future visual assets.

This is not a full brand book yet. It is the decision framework that ensures every visual asset supports Mutqan's operational positioning.

## Visual system philosophy
Mutqan visuals must explain operations, not decorate pages.

Every visual element should help users or prospects understand:
- How work moves.
- How assets gain memory.
- How locations create context.
- How evidence proves execution.
- How reports support decisions.

If a visual asset does not improve understanding or trust, it should not be used.

## Core visual principles

### 1. Connected systems over isolated objects
Mutqan should avoid random facility photos or generic maintenance illustrations as the main visual language.

The preferred visual language is based on connected systems:
- Nodes.
- Lines.
- Timelines.
- Layers.
- Cards.
- Signals.
- Records.
- Maps and location hierarchy.

The viewer should feel that Mutqan connects scattered operational data into one traceable system.

### 2. Operational meaning before visual style
Visuals should represent real operational meaning:
- A work order is not just a card; it is an event in a larger operational memory.
- An asset is not just equipment; it has identity, history, status, and risk.
- A report is not just a chart; it should point toward a review or decision.

### 3. Calm enterprise clarity
The visual style should feel:
- Calm.
- Structured.
- Mature.
- Technical but human.
- Enterprise-ready.
- Clear in Arabic and English contexts.

Avoid:
- Overly playful graphics.
- Consumer-app visuals.
- Random bright gradients.
- Decorative 3D without purpose.
- Stock photos that do not add operational meaning.

## Approved visual metaphors

### Operating Graph
Represents the connected journey:

Request → Location → Asset → Work Order → Execution → Proof → Asset Record → Report → Decision

Use it in:
- Landing pages.
- Sales decks.
- Product explainers.
- Demo visuals.
- LinkedIn educational posts.

### Asset Passport
Represents an asset as an identity with memory.

Possible elements:
- Asset name/code.
- QR code.
- Location.
- Status.
- Criticality.
- Last work order.
- Maintenance history.
- Warranty/lifecycle context.
- Risk or review signal when available.

### Proof of Work Card
Represents completed work as verifiable evidence.

Possible elements:
- Work order number.
- Location.
- Asset.
- Technician.
- Date/time.
- Notes.
- Photos or attachments.
- Approval history.
- QR or verification link when supported.

### Facility Pulse
Represents operational pressure or health at a facility/location level.

Use carefully. Do not present it as a current feature unless implemented.

### Decision Brief
Represents reporting that explains what matters.

Possible elements:
- Summary.
- Key risk.
- Repeated issue.
- Delay reason.
- Recommended review point.

### Timeline
Represents operational memory.

Use for:
- Work orders.
- Assets.
- Locations.
- Approvals.
- Audit logs.
- Proof of Work.

## Illustration style

Preferred style:
- Minimal.
- Geometric.
- Flat or semi-flat.
- Clear outlines.
- Limited color palette.
- Light technical feel.
- Clean spacing.

Avoid:
- Cartoonish characters.
- Heavy 3D as a default.
- Complex scenes that are hard to understand.
- Decorative facility images with no workflow meaning.
- Mixed illustration styles.

## Iconography principles

Icons should be:
- Consistent in stroke and style.
- Recognizable at small sizes.
- Functional, not decorative.
- Connected to operational meaning.
- Compatible with both Arabic and English layouts.

Use icons for:
- Status.
- Action.
- Category.
- Module identity.
- Risk or signal.

Do not use icons as visual noise.

## Product screenshot principles

A screenshot should never be shown as a raw image without meaning.

Every screenshot used in marketing or sales should include:
- Value title.
- Highlight area.
- Short explanatory caption.
- Operational context.

Example:
- Weak: screenshot of work order table.
- Strong: “See overdue work by location, asset, and responsible team in one view.”

## Color principles

Color must support hierarchy and meaning.

Color roles:
- Navy/ink: structure, trust, headers, core identity.
- Teal: action, connection, progress, positive signal.
- Paper: marketing warmth and storytelling.
- Cool surfaces: product workspace backgrounds.
- Amber: warning or review needed.
- Red: critical/destructive.
- Green: success/completion.
- Muted slate: secondary information.

Avoid using new colors without defining their role.

## Layout principles

### Marketing layouts
Marketing layouts may use more storytelling, spacing, and visual rhythm.
They should guide the viewer through an operational transformation.

### Product layouts
Product layouts must prioritize usability, scanning, and action.
They should minimize distraction and support daily work.

### Sales/documentation layouts
Sales and documentation layouts should be clear, structured, and example-driven.
They must make Mutqan easy to understand quickly.

## Visual governance checklist

Before approving any visual asset, ask:

1. What operational idea does this visual explain?
2. Does it connect to Mutqan's positioning as operational memory?
3. Is it consistent with the brand palette and tone?
4. Does it avoid overpromising features?
5. Can it work in Arabic and English contexts?
6. Can this style be repeated by future team members?
7. Does it increase clarity or trust?

## Employee onboarding summary

Mutqan visuals are not decoration. They are explanations of how operations become connected, traceable, and decision-ready. Use connected systems, timelines, proof cards, asset identity, and decision signals as the visual language of the brand.
