# Mutqan Visual Identity & Asset Reference v2.1

This folder is the visual source of truth for Mutqan v2 identity work.
It is a static HTML/CSS reference for designers, Codex, Figma builders, and Canva builders.

It is not a product implementation, not a business document, and not a content campaign.

## Visual Polish v2.1

This pass raises the reference from a plain HTML documentation set into a more polished visual system reference.
It adds calmer premium surfaces, stronger visual hierarchy, richer component examples, better PDF and social previews, and neutral operational sample data such as `AHU-03`, `Work Order 1024`, `North Wing`, `Asset Health 76`, `Evidence Added`, and `Pending Review`.

The intent remains the same: visual identity and asset reference only.

## Contents

- `index.html` - overview and visual asset inventory.
- `visual-identity.html` - visual tone, RTL/LTR behavior, and operating graph examples.
- `logo-system.html` - logo variants, safe area, favicon, app icon, and wrong usage.
- `tokens.html` - color and semantic token reference.
- `ui-kit.html` - core UI components and Mutqan-specific components.
- `pdf-social-templates.html` - PDF and social visual template previews.
- `motion-system.html` - motion scenes and storyboard rules.
- `handoff.html` - Figma, Canva, export, and repo handoff.
- `mutqan-brand-v2.css` - standalone visual system CSS.
- `assets/` - future logo, icon, pattern, and template asset locations.

## How designers should use it

Use the HTML pages as the reference for spacing, hierarchy, color use, component shape, and visual rhythm.
The logo shown here is a specification placeholder. The final vector artwork must be drawn separately from the approved direction.

## How Codex should use it

Use this folder as the source for future implementation planning.
Do not apply these tokens to product files unless a separate task explicitly asks for that.
When adding new visual references, keep text neutral and keep examples visual.

## How Figma and Canva should use it later

Use `handoff.html` to create design pages, component names, token names, export formats, and template specs.
Use the same color values, typography families, logo constraints, and template structure.

## Out of scope

- Product-wide UI changes.
- Final logo vector drawing.
- Business strategy.
- Commercial offer content.
- Future capability claims that are not implemented.
- Long narrative explanations.
