# استراتيجية إشعارات واتساب في متقن

الحالة: مؤجل كمسار مستقبلي  
المالك: المؤسس  
المشغل التنفيذي: Codex  
آخر تحديث: 2026-05-01

## 1. سبب الفكرة

في بيئات التشغيل والصيانة، البريد الإلكتروني ليس دائما قناة عملية. الفنيون والمشرفون في المواقع غالبا يستخدمون واتساب أكثر من البريد، خصوصا لاستقبال البلاغات والتنبيهات السريعة.

لذلك واتساب قناة مناسبة تشغيليا، لكن يجب إدخالها بحذر حتى لا تتحول الإشعارات إلى إزعاج أو وعود تقنية غير مستقرة.

قرار 2026-05-01:

البريد الإلكتروني هو القناة الرسمية المعتمدة حاليا. واتساب يبقى مسارا مستقبليا غير مفعل الآن.

## 2. القرار المقترح

نعتمد مسارا مرحليا:

1. الآن: إشعارات داخل النظام + بريد إلكتروني كقناة رسمية.
2. لاحقا: خيار مشاركة واتساب يدوي أو شبه يدوي إذا احتجناه.
3. بعد ذلك: WhatsApp Cloud API رسمي لتجربة محدودة وبموافقة صريحة.
4. مستقبلا: تطبيق جوال أصلي مع Push Notifications كقناة أساسية.

## 3. الحقيقة المهمة حول “المجاني”

واتساب Business App مجاني للاستخدام اليدوي، لكنه ليس قناة API مؤتمتة.

واتساب Cloud API الرسمي يمكن أن يكون منخفض التكلفة، وفيه نوافذ محادثة مجانية/غير مكلفة حسب نوع الرسالة وسياقها، لكنه ليس “مجاني بالكامل” للإشعارات التي يبدأها النظام.

قاعدة عملية:

- إذا أرسل المستخدم رسالة أولا، يمكن الرد عليه برسائل حرة داخل نافذة خدمة 24 ساعة.
- إذا بدأ النظام الرسالة خارج نافذة 24 ساعة، نحتاج غالبا قالبا معتمدا، وقد توجد تكلفة حسب نوع القالب والدولة.
- الرسائل التسويقية ليست مناسبة لإشعارات التشغيل.
- الإشعارات التشغيلية يجب أن تصنف كرسائل Utility متى أمكن.

## 4. ما لا نستخدمه

لا نستخدم حلول WhatsApp Web غير الرسمية أو مكتبات QR غير المعتمدة في بيئة مستشفى أو تشغيل حقيقي.

السبب:

- قد تخالف شروط واتساب.
- قد تتعطل فجأة.
- قد تعرض الرقم للحظر.
- يصعب حوكمتها أمنيا.
- غير مناسبة لأي بيئة حساسة أو عميل رسمي.

## 5. تجربة واتساب المقترحة

### المرحلة 1: مشاركة يدوية

نضيف في متقن زر:

`نسخ رسالة واتساب`

أو:

`فتح واتساب`

الرسالة لا ترسل تلقائيا، بل يراجعها المستخدم ثم يرسلها.

ميزة هذه المرحلة:

- مجانية تقريبا.
- آمنة.
- لا تحتاج اعتماد Meta.
- مناسبة للتجربة الضيقة.
- تكشف هل نصوص التنبيه مفيدة فعلا.

### المرحلة 2: قناة واتساب رسمية

نستخدم WhatsApp Cloud API الرسمي مع:

- رقم مخصص لمتقن أو للمنظمة.
- موافقة المستخدم على استقبال التنبيهات.
- قوالب Utility معتمدة.
- عدم إرسال تفاصيل حساسة.
- سجل تسليم لكل رسالة.
- حدود إرسال لمنع الإزعاج.

### المرحلة 3: تطبيق جوال و Push

عندما يصبح الاستخدام الحقيقي أكبر، التطبيق الجوال الأصلي يصبح القناة الأفضل للفنيين.

Push Notifications يجب أن تحمل:

- عنوانا مختصرا.
- نوع الحدث.
- رابطا يفتح شاشة أمر العمل.
- بدون تفاصيل حساسة خارج التطبيق.

## 6. أنواع الإشعارات المناسبة لواتساب

لا نرسل كل شيء.

نرسل فقط:

| الحدث | مناسب لواتساب؟ | السبب |
| --- | --- | --- |
| بلاغ جديد عالي الأولوية | نعم | يحتاج انتباها سريعا. |
| تعيين أمر عمل لفني | نعم | إجراء مباشر. |
| تأخر أمر عمل مهم | نعم | خطر تشغيلي. |
| اعتماد مطلوب من مشرف | نعم | يعطل سير العمل. |
| تغيير حالة عادي | غالبا لا | قد يسبب إزعاجا. |
| كل إشعار داخلي | لا | يخلق ضجيجا. |

## 7. صياغة آمنة للإشعار

مثال:

تم تعيين أمر عمل جديد لك في متقن.

النوع: صيانة  
الأولوية: عالية  
افتح متقن للاطلاع على التفاصيل واتخاذ الإجراء.

رابط: [رابط أمر العمل]

لا نضع:

- أسماء مرضى.
- معلومات صحية.
- تفاصيل موقع حساسة.
- وصف طويل للمشكلة إذا كان حساسا.
- أسماء أشخاص غير ضرورية.

## 8. المتطلبات التقنية قبل الأتمتة

قبل إرسال واتساب تلقائيا يجب بناء:

- جدول تفضيلات إشعارات للمستخدم.
- جدول تسليم إشعارات لكل قناة.
- منع التكرار.
- حدود إرسال يومية.
- سجل فشل ونجاح.
- قوالب رسائل معتمدة.
- صفحة إعدادات لكل منظمة.

## 9. الخطر الحالي

قاعدة البيانات أظهرت تضخم إشعارات في يوم 2026-04-25.

لذلك لا يجب توصيل واتساب مباشرة بجدول `notifications` قبل تنظيف منطق الإشعارات، وإلا قد يصل للمستخدمين عشرات التنبيهات لنفس السياق.

## 10. التوصية التنفيذية

نبدأ بتعديل صغير ومدروس:

1. إصلاح مسار البريد الحالي أو تعطيله مؤقتا.
2. إضافة زر مشاركة واتساب يدوي لأمر العمل.
3. إضافة إعداد تفضيل قناة الإشعار للمستخدم.
4. إضافة سجل تسليم إشعارات.
5. بعد ذلك نختبر WhatsApp Cloud API الرسمي على مستخدم أو مستخدمين فقط.

بهذا نثبت أن واتساب فعلا يحل ألم الموقع بدون الدخول مبكرا في قناة خارجية قد تولد تكلفة أو ضجيجا.
