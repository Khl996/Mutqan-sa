# خارطة أدوات وأتمتة متقن

الحالة: خارطة تنفيذ حية  
المالك: المؤسس  
المشغل التنفيذي: Codex  
آخر تحديث: 2026-05-01

## 1. الغرض

تحدد هذه الخارطة الأدوات التي نربطها، وما نؤتمته، وما نتركه يدويا حتى يثبت سير العمل.

الهدف ليس جمع أدوات. الهدف بناء سير شركة قابل للتوسع:

إشارة عميل -> تحليل إدارة مختصة -> قرار مؤسس -> مهمة تنفيذ -> دليل -> مراجعة.

## 3. قرارات الأدوات المقترحة

### القرار 1: CRM

الافتراضي لأول 30 يوما:

استخدام Notion كـ CRM مؤقت، إلا إذا قرر المؤسس البدء بخروج بيعي مكثف يحتاج HubSpot.

نستخدم HubSpot عندما:

- يتجاوز خط المبيعات 30 عميلا نشطا.
- تبدأ المتابعات تضيع.
- نحتاج تسلسلات بريدية أو مراحل صفقات أقوى.
- تصبح تقارير المبيعات صعبة في Notion.

### القرار 2: التقويم

تم ربط Google Calendar بالمراجعة التنفيذية الأسبوعية.

السبب:

- المراجعة التنفيذية يجب أن تكون متكررة.
- اجتماعات العروض تحتاج جدولة موثوقة.
- تواريخ المتابعة لا يجب أن تعيش في المحادثة فقط.

### القرار 3: البريد

نربط Gmail أو Outlook قبل زيادة حجم التواصل.

السبب:

- صياغة المتابعات.
- البحث في تاريخ التواصل مع العملاء.
- تلخيص الرسائل.
- استخراج الإجراءات التالية.

### القرار 4: أصول البيع

نستخدم Google Drive أو SharePoint أو مجلد محلي منظم حاليا.

الهيكلة المقترحة:

```text
أصول البيع/
  01 عرض التجربة/
  02 العروض التجارية/
  03 الصفحات المختصرة/
  04 لقطات العرض/
  05 قوالب المتابعة/
  06 مجلدات العملاء/
```

### القرار 5: التصميم

نضيف Canva أو Figma عندما نحتاج أول عرض أو ملف تجاري مصقول.

لا نقضي أسابيع في بناء نظام علامة كامل قبل بدء التواصل.

## 4. مراحل الأتمتة

### المرحلة 0: يدوي لكن موثق

نستخدمها فورا.

| العملية | الأداة | الناتج |
| --- | --- | --- |
| تسجيل القرار | Notion أو ملف المشروع | قرار مع مالك وتاريخ مراجعة. |
| المراجعة الأسبوعية | التقويم + Notion | ملاحظات مراجعة وإجراءات تالية. |
| متابعة العملاء المحتملين | Notion CRM مؤقت | خط مبيعات مع تاريخ إجراء تال. |
| تنفيذ المهام | Linear عند توفره، أو Notion مؤقتا | مهام وحالات واضحة. |
| تغييرات المنتج | GitHub | فرع، التزام، مراجعة، ودليل فني. |

### المرحلة 1: تشغيل المؤسس شبه الآلي

تبدأ بعد أسبوع من الاستخدام.

| الأتمتة | المحفز | الإجراء | المالك |
| --- | --- | --- | --- |
| أجندة المراجعة الأسبوعية | موعد أسبوعي | تجهيز أجندة من القرارات والمبيعات والمهام والعوائق. | Codex |
| تحويل القرار إلى مهمة | اعتماد المؤسس | إنشاء مهمة أو قائمة تنفيذ. | Codex |
| قائمة جاهزية العرض | حجز عرض | فحص مسار العرض، عدم كسر الوعود، وملاحظات الجاهزية. | الجودة + Codex |
| تذكير متابعة المبيعات | وصول تاريخ الإجراء التالي | صياغة متابعة وتحديث CRM. | المبيعات + Codex |
| مسودة عرض تجاري | فرصة جاهزة | مسودة من النطاق المعتمد وملاحظات التأهيل. | المبيعات + المالية + Codex |

### المرحلة 2: أتمتة المبيعات

تبدأ عندما يوجد 30 عميل محتمل أو تصبح المتابعات صعبة يدويا.

| الأتمتة | المحفز | الإجراء |
| --- | --- | --- |
| التقاط عميل محتمل | نموذج تواصل أو إدخال يدوي | إنشاء سجل CRM ومهمة تأهيل. |
| درجة الملاءمة | اكتمال التأهيل | حساب الملاءمة وإشارات الخطر. |
| متابعة العرض | انتهاء العرض | مسودة بريد، تحديث المرحلة، وتاريخ إجراء تال. |
| متابعة عدم الرد | لا رد بعد 3 إلى 5 أيام عمل | مسودة متابعة وتذكير. |
| سبب الخسارة | تعليم الصفقة كمفقودة | إلزام سبب وتعليم مستفاد. |

### المرحلة 3: أتمتة نجاح التجربة

تبدأ مع أول تجربة مدفوعة.

| الأتمتة | المحفز | الإجراء |
| --- | --- | --- |
| انطلاق التجربة | تجربة رابحة | صفحة حساب تجربة، قائمة إعداد، طلب بيانات، وأجندة انطلاق. |
| أول 7 أيام | تاريخ التشغيل | قائمة تبني يومية والتقاط العوائق. |
| تقرير قيمة أسبوعي | أسبوعيا أثناء التجربة | تلخيص الاستخدام، أوامر العمل، العوائق، وإشارات القيمة. |
| توجيه الملاحظات | وصول ملاحظة | تصنيف: علة، تدريب، ميزة، خطر نطاق، أو مشكلة بيانات. |
| مراجعة نهاية التجربة | قرب نهاية التجربة | مسودة تقرير قيمة وتوصية تحويل سنوي. |

### المرحلة 4: أتمتة الذكاء التشغيلي

تبدأ فقط بعد وجود استخدام عميل حقيقي.

| الأتمتة | المحفز | الإجراء |
| --- | --- | --- |
| سبب التأخير | تأخر أو تعليق أمر عمل | التقاط السبب وإضافته للتقرير. |
| صحة الأصل | اكتمال أمر عمل أو تفويت صيانة وقائية | تحديث درجة صحة الأصل. |
| بطاقة إثبات الإنجاز | اكتمال أمر عمل | توليد ملخص إثبات قابل للمشاركة. |
| تقرير قيمة التجديد | فتح نافذة التجديد | بناء حزمة أدلة من الاستخدام والنتائج. |

## 5. ما لا نؤتمته الآن

لا نؤتمت:

- اعتماد السعر النهائي.
- الخصومات.
- الالتزامات التعاقدية مع العملاء.
- قبول المخاطر الأمنية.
- تغييرات قاعدة الإنتاج.
- ادعاءات التسويق العامة.
- قرارات التوظيف.
- وكلاء معقدين يتصرفون بدون مراجعة.

هذه تحتاج مراجعة المؤسس أو التنفيذي.

## 7. مستويات تطبيق الوكلاء

### المستوى 1: مراجعة إدارة بالموجهات

استخدام يدوي داخل Codex.

الأفضل الآن.

أمثلة:

- إدارة المبيعات: راجع هذا العميل.
- إدارة المالية: راجع هذا الخصم.
- إدارة الأمن: راجع خطر هذا التغيير.

### المستوى 2: مخرجات منظمة

كل إدارة ترجع مخرجات وفق قالب ثابت.

يستخدم في:

- ملخصات التأهيل.
- مذكرات القرار.
- مراجعة نطاق العروض.
- تقارير التجربة.

### المستوى 3: إدارات تستخدم أدوات

تقرأ وتكتب في الأدوات، مع مراجعة للتغييرات المهمة.

يستخدم في:

- تحديث حالة عميل في Notion.
- إنشاء مهمة.
- صياغة بريد متابعة.
- قراءة سياق التقويم.

### المستوى 4: سير عمل شبه مستقل

يتصرف بناء على محفزات مع بوابات مراجعة.

يستخدم بعد نجاح متكرر:

- حجز عرض -> إنشاء قائمة جاهزية.
- فوز تجربة -> إنشاء مهام تهيئة.
- موعد متابعة -> صياغة بريد.

### المستوى 5: عمليات مستقلة

غير موصى به الآن.

لا ندرسه إلا بعد:

- ثبات سير العمل.
- تقييم المخرجات.
- اختبار حواجز الحماية.
- وضوح نقاط المراجعة البشرية.

## 8. قائمة تقييم أعمال الذكاء الاصطناعي

كل سير عمل متكرر يختبر ضد:

| التقييم | السؤال |
| --- | --- |
| الدقة | هل استخدم الحقائق الصحيحة؟ |
| ضبط النطاق | هل بقي داخل ميثاق الإدارة؟ |
| ضبط الوعود | هل تجنب ادعاءات غير مدعومة؟ |
| قابلية التنفيذ | هل أنتج إجراء واضحا؟ |
| قابلية التتبع | هل نرى المصدر والقرار والمهمة والنتيجة؟ |
| كشف المخاطر | هل أظهر ما يحتاج موافقة المؤسس؟ |
| قيمة الوقت والتكلفة | هل وفر وقتا كافيا يبرر الأتمتة؟ |

## 9. أول 10 أتمتات مقترحة

نبنيها بهذا الترتيب:

1. أجندة المراجعة الأسبوعية.
2. قالب سجل القرار.
3. ملخص تأهيل العميل.
4. تذكير الإجراء التالي للعميل.
5. مسودة متابعة العرض.
6. قائمة جاهزية العرض.
7. مسودة عرض تجاري من نطاق التجربة المعتمد.
8. قائمة انطلاق التجربة.
9. قائمة أول 7 أيام لنجاح العميل.
10. مسودة تقرير قيمة التجربة.

## 10. الخطوات الفورية

1. اختيار CRM: Notion لمدة 30 يوما أو HubSpot الآن.
2. إنشاء قواعد Notion: القرارات، خط المبيعات، حسابات التجارب، الإجراءات، ملاحظات العملاء.
3. إنشاء مراجعة تنفيذية أسبوعية في التقويم عند اعتماد الموعد.
4. تحويل وثائق البيع إلى صفحات Notion أو أصول بيع.
5. بناء خط أول 30 حساب.
6. استخدام مواثيق الإدارات في كل تحليل جاد.

## 11. توصية الربط

مطلوب الآن:

- Google Calendar أو Outlook Calendar.
- Gmail أو Outlook Email.
- Google Drive أو SharePoint.
- HubSpot فقط إذا قرر المؤسس CRM مخصصا من اليوم الأول.

مفيد لاحقا:

- Slack بعد وجود فريق.
- Helpdesk بعد وجود حجم عملاء.
- n8n أو Make أو Zapier بعد تكرار العمليات.

غير مطلوب الآن:

- إدارة مشاريع مؤسسية ثقيلة فوق الحاجة.
- مستودع بيانات معقد.
- منظومة تسويق آلي كاملة.
